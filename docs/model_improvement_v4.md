# 추가 성능 개선 실험 v4

## 실제 결과

추가 실험은 성공한 후보만 골라 보고하지 않는다. 개선 가능성을 확인했지만 이번 후보는 기존 v3를 넘지 못했고, 운영 모델 승격 조건도 충족하지 못했다.

| 평가 구간 | 7일 평균 WAPE | 기존 v3 WAPE | 추가 v4 WAPE |
| --- | ---: | ---: | ---: |
| 앞 Validation: 후보 선택 | 49.7324% | 50.0460% | **46.9347%** |
| 뒤 Validation 14일: Gate | **15.1524%** | **14.8769%** | 24.2225% |
| 기존 Test: 같은 1,123 origins × 24h | 33.8924% | **33.8185%** | 34.0215% |

00시에서 다음 24시간을 예측하는 운영 방식도 따로 확인했다. Test 47일 기준 v4 WAPE 35.2226%, 7일 평균 33.7748%다. 시간별 rolling origin의 전체 결과만 보고 운영 품질을 판단하지 않는다.

## 후보와 선택 방식

기존 평균 외에 7일 중앙값, 최근 3일 중앙값, 7일 35%/65% 분위수, 최대·최소를 제거한 평균을 비교했다. 기존 설치된 scikit-learn 트리 모델에도 7개 동일 시간 lag, 평균/중앙값/표준편차/최소/최대, 7일 일평균, 가장 최근 6시간 관측, 예측 horizon, 미래 달력 특징을 넣었다. 입력은 예측 시점 이전 관측과 이미 알려진 시각만 사용한다.

트리는 Train만으로 학습했다. 고정 후보 목록과 트리 설정을 `plan.json`에 먼저 저장하고 앞 Validation WAPE가 가장 낮은 후보를 골랐다. 뒤 14일 Gate나 Test로 후보를 재선택하지 않았다. 선택한 enhanced_tree의 결과를 확인한 뒤 추가 설정 검색은 하지 않았다. Test는 이전 작업에서 이미 여러 번 확인한 기간이므로 완전한 신규 평가 기간은 아니며, 독립적인 미래 데이터가 필요하다.

상한 40% 및 기존 Production/단순 평균 중 좋은 쪽보다 WAPE 5% 이상 개선하는 개발용 Gate를 그대로 적용했다. 같은 Gate 구간의 7일 평균 WAPE 15.1524% × 0.95 = 14.3948% 이하가 필요했지만 후보는 24.2225%였다. **Gate FAIL**이며 API·MLflow Production·Docker·기존 임계값을 변경하지 않았다. 40%는 사업 SLA나 산업 표준이 아니다.

## 다음 개선 방향

현재 입력은 2025년 한 지역의 태양광 전력거래량 이력과 달력이다. 더 큰 모델을 쓴다고 새로운 정보가 생기는 것은 아니다. 이번 결과만으로 정확한 성능 상한이나 오차의 원인을 단정할 수 없지만, 관측 이력만을 변형한 모델의 개선이 새 구간에서도 유지되지는 않았다.

다음에는 예측 시점에 이용 가능한 **기상예보**(일사량·운량 등)와 지역 설비 용량/변경 이력을 확보하고, 여러 계절/연도의 데이터를 시간 순서로 평가하는 것이 우선이다. 과거 날씨 실측은 분석이나 학습에 쓸 수 있지만 미래 target 시간의 실측 날씨를 입력으로 사용한 평가를 실제 예보 성능으로 보고하면 안 된다. 예보 자료는 발행 시각과 유효 시각을 보존하고 예측 시점 전에 발행된 자료만 연결해야 한다. 외부 데이터는 이번 작업에서 임의로 추가하지 않았다.

태양 고도만으로 밤 출력을 강제로 0으로 만드는 처리는 도입하지 않았다. 현재 원본 전력거래량에는 저녁/야간의 0이 아닌 값도 있어, 발전량과 거래량의 시간 대응/집계 의미를 먼저 확인해야 한다. 물리적으로 그럴듯한 처리로 원본 정답을 바꾸지 않는다.

30% 이하 목표는 유지하되 달성했다고 발표하지 않는다. v3 33.82%가 이번 작업까지 확인된 가장 낮은 동일 Test 결과이며, 단순 평균보다 차이가 작다는 기존 한계도 유지한다.

## 파일 및 재현

```bash
.venv/bin/python scripts/train_baseline_v4.py
.venv/bin/python tests/check_model_v4.py
```

이미 결과가 있으면 학습 스크립트는 덮어쓰지 않고 종료한다. 로컬 결과는 `artifacts/model_v4/`이며 검토용 작은 JSON/CSV와 비교 차트는 `reports/model_v4/`에 보존했다. 로컬 후보 파일은 `serving_app/models/baseline_v4.pkl`이며 기존 ignore 정책으로 Git에 포함되지 않는다.

검증은 후보 선택 규칙, 동일 Test target, 미래 target 변경 시 feature 불변, 저장/재로딩 예측 일치, Gate 판정, 기존 파일 SHA-256 보존을 확인한다. `src/model_v4.py`의 inference 함수는 실험용이며 현재 운영 서버에 연결하지 않았다. 기존 패키지만 사용했다.

기술 참고: [scikit-learn HistGradientBoostingRegressor](https://scikit-learn.org/stable/modules/generated/sklearn.ensemble.HistGradientBoostingRegressor.html).
