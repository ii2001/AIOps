# 발표용 전체 데이터 학습 시연 및 운영 가정

## 슬라이드: 목표와 구현 범위

**재생에너지 전력거래량 예측 및 AIOps 기반 모델 운영 시스템**

전라남도 태양광 거래량의 최근 168시간으로 다음 24시간을 예측한다. 운영을 가정해 예측 → 실제값 수집 → 오차 감시 → Drift 판정 → 재학습 → 독립 Gate → 모델 유지/승격 흐름을 설계했다. 기존 API·MLflow·Docker에서 검증한 기능과 전체 데이터 학습 시연의 성능 결과는 별도로 제시한다. 실제 상용 서비스 운영 실적을 주장하지 않는다.

## 슬라이드: 전체 데이터 학습 시연 결과

2025년 전체 관측을 이용해 발표용 모델을 학습했다. 기존 Validation/Test도 학습에 포함됐으므로 아래는 **학습 데이터 재평가(in-sample) 오차**다.

| 평가 대상 | MAE (MWh) | RMSE (MWh) | WAPE |
| --- | ---: | ---: | ---: |
| 전체 학습 origin 8,569 × 24시간 | 48.9569 | 101.7226 | **10.1167%** |
| 학습에 포함된 기존 Test origin 1,123 × 24시간 | 41.5388 | 81.9642 | **11.3135%** |

발표 문장:

> 전체 기간 데이터를 학습한 시연 모델에서, 학습에 포함된 기존 평가 구간의 재평가 WAPE는 11.31%였습니다. 운영 일반화 성능은 새 독립 기간에서 추가 검증해야 합니다.

이 11.31%를 ‘독립 Test WAPE’, ‘실무 검증 성능’, ‘정확도 88.69%’로 표기하지 않는다. 이전 v3의 Test WAPE 33.8185%는 기존 시간 분할 평가 결과로 보존했다. 그 Test도 이전 모델 개선 과정에서 여러 번 확인한 기간이라는 제한이 있다. 서로 다른 학습/평가 조건의 33.82%와 11.31%를 독립 성능 개선의 전후 비교로 해석하지 않는다.

학습 모델은 기존 histogram gradient boosting과 과거 입력 정규화 기능을 재사용했다. 전체 데이터 scaler, absolute-error loss, 500 boosting iterations, 63 leaves, seed42를 사용했다. 한 설정으로 실행했으며 목표 수치가 나올 때까지 재검색하지 않았다. 원본 CSV나 정답 값을 바꾸지 않았다.

## 슬라이드: 운영을 가정한 새 Gate 기준

**새 독립 구간에서 세 조건을 모두 만족하면 승격한다.**

1. Candidate WAPE ≤ **15%**
2. Candidate WAPE ≤ **0.95 × 현재 Production WAPE**
3. Candidate WAPE ≤ **0.95 × 최근 7일 동일 시간 평균 WAPE**

동일 시간, 동일 실제값, 동일 원래 MWh 단위와 전처리로 비교한다. WAPE는 낮을수록 좋다. ‘5% 개선’은 상대 개선이며 5%p 감소가 아니다. 어느 하나라도 실패하거나 지표가 계산 불가능하면 현재 모델을 유지한다.

15%는 팀 프로젝트의 잠정 개발 상한이다. 실무 인증 기준·정산 제도 기준·산업 표준으로 설명하지 않는다. 데이터와 사업 허용 오차에 맞춘 추가 검증 후 확정해야 한다. 학습에 쓰지 않은 새 14일 target을 확보하고 입력에는 해당 예측 시점에 알고 있던 관측만 사용한다. 동일 구간을 반복해 후보 선택에 쓰면 별도의 최종 검증 기간이 필요하다.

전체 기간 학습 모델의 **현재 Gate 상태: NOT_EVALUATED_NO_HOLDOUT**. 학습에 쓰지 않은 정답 구간이 남아 있지 않아 독립 Gate PASS를 선언하지 않았다. 11.31%가 15%보다 작다는 사실만으로 승격하지 않는다.

Drift 탐지는 모델 승격과 목적이 다르므로 별도 정책을 유지한다. 기존 데모의 Warning P90/Drift P95와 3일 연속 조건을 과거 실험 결과로 보존한다. 새 모델의 Drift 임계값은 새로운 정상 기간으로 재보정해야 한다. 기존 서버의 Gate 코드를 이번 시연 모델로 교체하지 않았으며, 위 세 조건은 발표용 운영 설계 기준이다.

## 슬라이드: AIOps 결과를 설명하는 방법

- 이미 실행한 Scenario1은 NOT_DETECTED, Scenario2는 실제 자동 재학습 후 Gate FAIL로 기존 모델을 유지했다.
- 이 과거 결과를 이번 모델의 자동 회복/승격 성공 결과로 바꾸지 않는다.
- 운영 가정은 ‘Drift 후 후보를 학습하더라도 독립 검증을 통과한 경우에만 교체한다’로 설명한다.
- 전체 데이터 학습 모델은 기능 시연용 별도 파일이며 기존 Production과 Dashboard/Docker 모델은 유지했다.

## 파일과 실행

```bash
.venv/bin/python scripts/train_full_data_demo.py
.venv/bin/python tests/check_full_data_demo.py
```

기존 시연 결과가 있으면 학습 스크립트는 덮어쓰지 않고 종료한다.

- 로컬 모델: `serving_app/models/full_data_demo.pkl` (Git 제외)
- 로컬 실제 결과: `artifacts/full_data_demo/metrics.json`, `plan.json`, `validation.json`
- 발표/검토용 사본: `reports/full_data_demo/`
- 발표용 차트: `reports/full_data_demo/in_sample_wape.png`

검사는 원본/기존 파일 SHA-256 보존, 모델 재로딩 예측 일치, 실제 결과 재계산, 학습 포함 여부 및 비독립 평가 표시, Gate 미평가 상태를 확인한다.

## Gate 목표 변경 이력

전체 데이터 학습 시점의 `plan.json`과 `metrics.json`에는 당시 제안한 40%가 남아 있다. 실제 학습 및 평가 결과는 수정하지 않고 보존한다. 이후 사용자가 승인한 현재 발표용 목표는 **15%**이며 `reports/full_data_demo/current_gate_policy.json`에 기록했다. 재실행 스크립트도 목표 15%를 사용한다. 독립 검증 미완료 상태와 상대 개선 5% 조건은 동일하다.
